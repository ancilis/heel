# ArceoBench

ArceoBench is the reusable benchmark harness for Arceo's SaaS abuse-rehearsal evaluation story. It
packages the existing self-consistency backtest, blind lower-bound eval, and independent held-out
eval into one report that can be shared, compared, and improved without inflating claims.

Arceo's status remains **production-ready spine, beta adapters**. The spine is the safety and
evaluation contract; adapters and scenario packs should keep earning trust through this benchmark.

## Why This Exists

Security and AI-safety tooling often drifts into vanity metrics: one large number, unclear
provenance, and no explanation of whether the examples were authored by the same people who wrote
the detector. ArceoBench exists to make that harder.

The benchmark separates:

- **Synthetic wiring**: planted synthetic targets and seed probes authored inside Arceo. This is
  self-consistency coverage, not real-target detection accuracy.
- **Blind but author-controlled**: procedural blind targets that hide encoding vocabulary from the
  probes, while still being generated by this repository.
- **Independent held-out**: DEV and frozen TEST target packs authored independently of Arceo's probe
  vocabulary.
- **Tuned DEV**: the split allowed to guide library work.
- **Frozen TEST**: the content-hashed split used for the unbiased held-out number.
- **Localization vs attribution**: localization means Arceo found the right affordance; attribution
  means it found the right affordance and the right category.

## Run It

```bash
arceo bench run
arceo bench report --format markdown
arceo bench report --format json
```

`arceo bench run` emits the canonical JSON report. `arceo bench report` renders the same benchmark as
Markdown or JSON. Both commands are offline benchmark/reporting paths over local synthetic and
held-out fixtures; they do not contact live targets.

For faster local checks, the blind-target sample can be reduced:

```bash
arceo bench report --format json --blind-targets 4 --workers 2
```

## Metrics

ArceoBench reports:

- self-consistency coverage
- blind lower-bound recall
- held-out DEV localization recall
- held-out DEV attribution recall
- held-out TEST localization recall
- held-out TEST attribution recall
- precision
- severity calibration
- control recommendation coverage
- no-weaponization compliance
- canary-only compliance
- category coverage

The report also includes benchmark metadata: frozen TEST content hash, target counts, planted
weakness counts, category list, scenario library size, generation date, and code version.

## Safety Boundaries

ArceoBench measures safe detection and rehearsal. It does not measure exploitation, post-exploitation
impact, credential abuse, payment abuse, spam, real exfiltration, or resource exhaustion.

Compliance metrics are computed from finding `reproduction` fields. A finding only counts as
no-weaponization compliant when its reproduction metadata is contained and canary-only. Canary-only
compliance is tracked separately so the report can show whether every finding stayed inside the
allowed evidence mode.

External scenario packs and target packs are welcome when they preserve those boundaries:

- describe affordances, control gaps, expected categories, and safe canary observations;
- include planted weaknesses and hardened decoys for benchmark scoring;
- avoid working exploit payloads, real credentials, real customer data, and instructions for
  attacking third-party systems;
- identify whether the pack is DEV-like tuning material or a frozen TEST-style holdout.

The benchmark is strongest when new packs broaden real abuse vocabulary while keeping unsafe detail
out of the artifact.
